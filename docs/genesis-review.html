What is good, what is bad, what is missing, and what would be new

Two independent reads of the repository, one as a first-time user looking at the real screens, one as an engineer looking at how it is built. Every claim below was checked against the code or the release list before it went on this page. Each item now carries what has actually happened since, checked the same way.

1 · Good: what a user would really notice

Permission cards in plain verbs, with the safe button focused

"Genesis wants to install software", Allow once / Not now, as a proper alert dialog, the same card on the phone. Neither Copilot nor any Ollama front end does this.

The plan card and the inspectable undo

Four chips for what a job will touch before it runs; afterwards a per-file diff with "Restore just this file". No desktop assistant on Windows or macOS shows you what it changed.

It is honest about the hardware

The small-model warning, "still working, 40 s, not waiting on anything", measured tokens per second in Settings, a live "no network used" badge that matches the dock widget.

Spoken risky words need Enter; text from the phone is a draft

Two cheap, correct safety decisions that most voice products skip.

The broker is the best-tested code, and CI is real

24 broker tests, the policy dumped and diffed on every build, a serial-console boot test, a weekly upgrade canary, a scored ten-make evaluation, signed images, base images pinned by digest. The decision log records failures as plainly as successes.

2 · Bad: what would embarrass us in front of a reviewer

done There is no Stop button fix first

A make can run for six minutes and the daemon has no stop, cancel or interrupt anywhere. This is the first complaint of the first day.

done The guide promises things the screens do not have

"Allow for this project" (only Allow once exists), modes called Assist / Auto edit (the UI says Ask / Trusted / Hands-off), an "Apply at next restart" click (no such button), cloud keys "configure later in Settings" (no place to enter them), a "session summary" that does not exist.

done The palette turns every question into a build job

The guide says the answer appears in the same window; the code always redirects to the maker. "What is the capital of…" gets a plan card and a project folder. Nothing routes between asking and making.

done, and a light theme Two design systems, one undefined colour

Chat has its own palette, font and button style; the maker and Settings use another; backgrounds differ page to page; the maker uses --muted without defining it, and Settings uses three classes that have no CSS.

done: six entries, own icons, the start page folded Too many doors, all with the same icon

13 desktop entries, 6 global shortcuts, 3 more in Babel, one in the terminal; four identical ring icons in the dock. The maker start page stacks fifteen blocks; a gallery card has seven buttons.

done Jargon and raw internals on screen

sandbox: bubblewrap, "MCP", "server", "tier", "Role", /var/lib/genesis/models, running · auto_edit, tool calls as raw JSON, undo history listed by job id instead of by what was asked.

done Paths typed by hand on a desktop OS; native alert boxes for errors

Files to search, backup restore and chat attachments are text fields for an absolute path. Errors are alert(), a bare "Failed", or a "‼" chip. Chat's microphone posts a different audio format than the other pages.

done: testing and stable channels, local builds work again Every push ships to users, and CI is the only test bed

A push to main moves the tag installed machines update to, gated only by a weekly canary. About 90 human commits in three days, three of the last nine builds red, each failure found after a 90-minute wait. A red canary holds the stable tag silently; a green one from six days ago vouches for today.

done: separate files, checked and tested by CI The UI is 160 KB of untested one-line JavaScript

The maker page has a line 10,056 characters long. No lint, no syntax check in CI, no diffable history. The 2 tests for the 709-line policy file and the 1 test for the agent loop are in the same category: the most intricate behaviour is the least tested.

by design now: a socket for programs, the port for the pages, every route token-gated Security is still one token on loopback

Yesterday's audit closed the holes it found, but the structure invites the next one: 25 GET routes with a hand-kept list of which need the token, a shell that shares the loopback when it has network, an unauthenticated Ollama door, tools that run as the user. Moving the APIs to Unix sockets under the runtime directory removes that whole class at once.

4 · New: ten "wait, what?" ideas not in the current plan

Each builds on code that exists, fits a small local model, and shows in fifteen seconds. Most exploit being the operating system, which an app cannot. Seven of the ten are built (1 to 6, 8 and 10 below); the three left are the desktop widget from a sentence, the phone as microphone, and the sixty-second demo, which was already built earlier.

built 1. Right-click a file, "Make a tool for this" S

A CSV becomes a viewer, a photo folder a gallery. A Dolphin service menu plus the draft and project parameters the maker already takes. Keep it to five file types so the 2B model stays in its depth.

built 2. "Undo the last ten minutes" in the panel S

The time machine leaves Settings and becomes a button in the dock widget: what changed, thumbnails of the diffs, one click back. Undo as an OS feature.

built 3. Pull-the-cable proof S

One click takes the network down for sixty seconds while a make runs, a big "offline" badge, then restores it. The privacy claim, demonstrated. Restoring must be bulletproof.

built 4. Terminal rescue S

A command fails in Konsole and a dim line offers "Ctrl+G: explain and fix"; the fix lands as an editable command. Only on non-zero exits.

built 5. Clipboard transforms M

Select text anywhere, Meta+Shift+Space, five chips: fix grammar, shorter, to German, to Slovenian, to checklist. The result replaces the selection. Uses the no-tools session Babel's Ctrl+I already uses.

built 6. A made app gets its own key and window S

After Install, pick a Meta key; the app opens in a native-looking Genesis window. Fifteen seconds from sentence to shortcut.

7. A desktop widget from one sentence M

"Battery and my next calendar entry on the desktop" becomes a web plasmoid fed by the system tools.

built 8. Screenshot to app S

Meta+Shift+A over any app, "make me something like this"; the vision description seeds the maker. Framed as "inspired by", because a likeness from a 2B model will be loose.

9. The phone as microphone and remote M

Hold to talk on the phone; the desktop maker opens and builds while you watch.

built 10. The morning card, spoken S

At the first login of the day, in your language. Needs the off switch from section 3, which it then also delivers.

6 · What the two days actually produced

Before the first hardware install

The model service could not open the GPU on any real machine (a device rule named a directory, which systemd ignores), and the installer ISO shipped a test account with a known password and an SSH switch. Both fixed and verified. Also: big models fit themselves to free GPU memory, Intel Arc memory is detected, and the wizard leaves the Wi-Fi icon reachable.

Security, after the audit of the new code

The agent could have read the page token over the shared loopback and answered its own permission cards; it cannot now. The files that decide its permissions are protected, a home overlay cannot loosen the never tier, and a conversation that has read your documents must ask before going online.

Tests, which paid for themselves immediately

The new Python suite found four defects in the Ollama door and the file index the day it was written. The new Stop test failed in CI and was right twice over: killing a shell left its children running, and the fix shelled out to a program a minimal Linux does not have.

What this pace costs

Three builds in a row were red on the same test, each found ninety minutes later. Docker being down for two days hid a platform bug that a local Linux container found in two minutes once it was back. The lesson is the engineering review's: a local loop is not a luxury.

7 · What is left

Nothing open from the bad list

Ten of the eleven are closed. The eleventh is a stated limit rather than a gap: the pages are a browser, so the loopback port stays for them, token-gated, while local programs use a socket a sandboxed command cannot reach.

Two of the ten ideas

A desktop widget from one sentence, and the phone as a microphone and remote for a make. Both are a week's work rather than an evening's, and neither is in the way of anything.

The number itself

7 of 10 on the small model, where it was 9 before today. Three of the causes were changes made today to improve reliability, which is the argument for the evaluation existing.

Real hardware

Still nothing. Everything above was proved in virtual machines, on one phone and in one Linux container.
