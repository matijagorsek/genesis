You: what is the difference between Flatpak and a normal package here?
Genesis (Qwen3.5-2B, on this machine): On Genesis the base system is a read-only image, so apps install as Flatpaks in your user space. They update independently of the OS and can be removed without a trace. Command-line tools go into a toolbox container instead.

Nothing leaves this computer

Every answer, every file the assistant reads, and every action it takes stays on this machine. There is no account, no telemetry, and no cloud unless you add a key yourself.

What the assistant can see

Files you open or point it at. Your screen only when you ask, through a system dialog each time. Never the camera or microphone without a prompt.

What it can change

Files in projects freely. Settings and app installs after you approve. The base system never without a rebuild. Every change can be undone.

Optional cloud models

Add your own API key later in Settings. When a cloud model answers, the indicator turns amber and says so.

What is real today and what is not

  • Real: the three models, their speeds, the router that keeps the small model hot and swaps the coder, and the kanban app itself. All from the Phase 0 run on your Mac.
  • Designed, not built: the boot image, first-run wizard, desktop integration, launcher, workspace, permission broker, model manager and undo. These are Phase 1 and 2.
  • The permission prompt is the priority. In the real Phase 0 run the agent installed a package with a policy override without asking. Screen 8 is what should have happened.
