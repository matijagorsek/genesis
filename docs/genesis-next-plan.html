The next plan, and the three things it found wrong first

Two investigations: what the operating system makes possible that Genesis has not used, and what the models already on disk can do that nothing calls. The first answer was not a feature. It was that three pieces of this week's work were quietly making Genesis worse, and one of them had been poisoning the only number we steer by.

1 · What was wrong, and is now fixed

A shipped test that failed every correct program

Every command-line make inherited test___name__.py, which asserts the placeholder's behaviour: dice.py a b --json printing "count": 2. So the moment the model wrote a real dice roller the template's own test went red, the preview reported FAILED, and the model thrashed against it. Five of the ten evaluation makes are command-line shaped; four of them appear in the failure lists of decisions 106, 116, 119 and 139. Template tests now check only that the program starts and answers --help.

The conversation was being rewritten behind the model

trim_context, added on 17 September to keep within a 16k window, edited messages that had already been sent. The model service reuses its work by matching the start of a conversation; changing an old message moves the divergence point and makes it re-read everything, every turn. That is the likeliest cause of the runs that took two to four times longer, which I had blamed on tool schemas. Output is now cut when it is added and never afterwards.

The number we steer by could not support the claims made from it

A make counted as passed when the session ended and a file was written — nothing checked the program did what was asked — and no seed was sent, so two runs of the same tree differ by sampling alone. Decisions 138, 139 and 140 attribute score movements to specific code changes; that attribution is not sound at n=1. The evaluation now fixes a seed, checks that what was made resembles what was asked, and reports finished and correct as two numbers.

Also fixed the same day: the reranker and completion model now ship in the CPU pack, where their code sat idle; draft is a legal pack role and the publish job refuses a pack that is off schema; the pages take dark or light from the window instead of guessing; an empty box that appeared above the start page on every visit is gone.

2 · Make the small model better, in the order I would do it

These are about technique, not more guards. Most people's first experience is a 2B model on a CPU, and that is where Genesis is judged. Effort: S a day · M a week.

SCPU Hand back the file with the scaffold

The compact script's second step is "read the entry file" — a whole model call plus a tool call, forty to ninety seconds, for content Genesis has on disk. The scaffold result should carry it.

Builds on the scaffold tool in agent.rs. Saves a turn and removes the wrong-path failure class.

SCPU Insist on an action while nothing has been written

The rule "never finish before you changed a file" is enforced after the fact, by spending a turn telling the model off. The model service can be told that a turn must be a tool call, so prose is not possible until the work exists.

One parameter through Client::chat. Replaces a wasted turn with a constraint.

MCPU One worked example instead of more instructions

The compact prompt is 244 tokens of instruction and zero demonstration. A 2B model imitates far better than it follows. One complete example — request, a whole file written, a run, a two-sentence summary — is the largest single lever in this list.

Costs about a thousand tokens of prefix, which is free once the prefix stops being invalidated.

MCPU Pick the template with the embedder, not the model

Asking a 2B model to choose a template id from a list in prose is a turn spent on something an embedding comparison does in fifty milliseconds — and every pack already ships the embedder, always loaded.

Removes two tools from the small-model schema and starts the conversation two turns in.

SCPU Use the plan we already pay for

The plan card makes a model call, shows the steps to the user, and throws them away: they are never put into the conversation. A small model follows its own plan better than a list of rules.

3 · New capability from models already on disk

SCPU Read anything aloud — built today

Select text anywhere, Meta+Shift+R, and the local voice reads it; press again to stop. Every pack ships three voices and they were used for one card a day.

MCPU Transcripts with timestamps, and subtitles

Whisper computes timestamps and Genesis throws them away. Right-click an audio or video file: a clickable transcript, an .srt next to the video, and the spoken words added to the file index so search finds them.

MCPU, once per make Genesis looks at what it made

The small model on most packs can see. After a preview, one screenshot and one line under it: "a countdown, a Start button, no bell control visible." Shown to the person, never used to fail a build — a 2B model's visual judgement is not good enough for that.

SCPU "I could not find this" instead of an invention

When nothing in your files scores above the reranker's threshold, chat should say it does not know. The most damaging failure of a small local assistant is a confident answer from memory.

4 · What the operating system makes possible and Genesis has not used

The image has no udev rules, no sleep hooks, no inhibitors, one file-manager menu and one polkit rule. These are the empty hooks worth filling.

SCPU Undo an app install from the panel

Chat installs an app; the panel says "installed · Undo"; one click removes it. The install is already recorded in the same transaction that powers Undo — this is plumbing, not new machinery. It should say plainly that it keeps the app's settings.

SCPU A job survives the lid

Close a laptop during a make and it comes back broken. An inhibitor while a job runs, and a sleep hook that pauses and resumes cleanly. It matters most on the machines where a make takes twenty minutes.

Risk worth naming: an inhibitor that leaks keeps a laptop awake in a bag. It must be capped and released on the failure path, not only the happy one.

SCPU Ask this computer about itself

"Why is my disk full?" answered with the three biggest folders. "What is using my microphone?" answered with the app's name. Small read-only tools next to the ones that already exist.

MCPU Roll the whole system back, from the panel

After a bad update: "Go back to yesterday's version", one click, reboot. The status the panel already reads includes the previous deployment. The card must say what a rollback does not fix, or people will click it for a full disk.

MCPU Plug in a stick, get one card

"47 photos and 3 PDFs on this drive. Make a tool for them?" — and, if there is room, "back up what Genesis made to it."

The line that must not be crossed: count file types and stop. Never read, index or describe the contents of someone's drive without being asked. If that line ever moves, this feature should be deleted.

LCPU Dictate into any field, in any app

Hold a key anywhere, speak, and the text appears where the cursor is. The permission tier for sending input to the desktop was written on day one and has never been used. The hard part is doing it as a real input method rather than a fake keyboard, and text landing in the wrong field is a bad failure.

5 · What I will not build, and why

A camera plugged in, described

Technically a day's work: the vision model is already there. It is also the fastest way to destroy the one thing this project sells, and it contradicts the rule against always-on capture. No.

Summarising your notifications

It requires subscribing to mail, messages and banking alerts: continuous capture of the most sensitive stream on the machine, for a small convenience.

Anything on the lock screen

A lock screen is visible to whoever walks past. Job names and summaries are the user's work, shown to strangers.

Speculative decoding on CPU, and grammars over tool calls

On four cores generation is bound by memory bandwidth, so a draft model competes for the bottleneck instead of relieving it, on machines where the model service was already being killed for memory. And a tool-call grammar is already installed by the model service; the failures were semantic, not syntactic.
