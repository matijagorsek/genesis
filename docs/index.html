Ask

      
Your computer explains itself.

      
The same model that makes things reads the machine — the journal, the package database, the hardware. Not a chatbot bolted on the side. What you see on the left is real output, captured on a real laptop with a real update waiting.

    

  

  

    
CRASH
A program stops. It says why.
One notification, one button. The program, the signal and the stack go to the model here, which reads the journal around that moment and answers in plain words. A crash dump carries the paths a program had open — exactly why it never leaves.

    
SERVICE
"backup.service failed" becomes "your disk wasn't plugged in."
Ten times more common than a crash, and just as opaque without this. Same offer, same door.

    
SCREEN
Draw a box on anything.
Meta+Shift+A: an error, a chart, a form — asked about with a vision model on this machine. Select text and right-click for the same.

    
VOICE · PHONE
Speak, or send it from your phone.
Meta+Shift+V listens. Share text starting with "ask" from the phone and the answer comes back as a notification. Anything that would install, delete or send is shown first and needs Enter.

    
BATTERY
It follows the plug.
Unplug a laptop and the big models are put away; every question goes to the small one, and the assistant gets shorter rather than quiet. Plug in, and they're back. Only a desktop that owns both the model and the machine can do this.

    
MEASURED
It measures your machine instead of guessing.
First run generates a few tokens on every device — CPU, each GPU — and keeps what was actually fastest. On the first real laptop that was the processor, not the built-in graphics, by three to one.

Kept

  
Updates like an appliance. A stable channel that's tested by asking.

  
Genesis is an image, not a pile of packages. Updates are fetched in the background and applied when you restart — never on their own — and the image you were on stays as the rollback, every time.

  

    
NIGHTLY CANARY
Stable only moves after a machine proved it.
Every night a machine installed a week ago is upgraded to the new image, rebooted, and checked: does it boot, does it set itself up, does the assistant answer? A build that fails never reaches you.

    
ROLLBACK
Pick the previous entry in the boot menu.
That's the whole procedure. Nothing to reinstall.

    
CATALOGUE
Fifty apps with a reason each.
Not a store with forty thousand. One answer per need, one word to install — genesis-apps install obsidian — and the assistant reads the same list. The image underneath is never touched.

    
SIGNED
Images signed, packs signed, downloads checked.
Every image carries a cosign signature; every model pack definition is signed and every download is checked against it.

  






  

    
What leaves the machine

    
Nothing, by default.

    
The models run here. The crash you ask about, the screen you draw a box on, the files you opt in — none of it is uploaded, because there is nowhere for it to go. Genesis makes three kinds of connection on its own, and that's the list:

    
  • Fetching updates
  • Downloading the model pack you chose
  • Installing the apps you asked for
  • …and one clearly labelled exception: Claude Code with your own account, off until you sign in

    
Some things it never does whatever you answer: read your keys and passwords, wipe disks, change the base system. Refused by rules, not by the model's judgement.

  






  
Honest

  
Proven on one laptop. Here's what that means.

  
Everything above was run on a real machine before it was written here, and the things that failed when it was — and there were several — are in the decision log with what was done. Which file do I need?

    
    
      
  • PC or laptop (x86_64): the installer ISO writes Genesis to a machine or a VM. The qcow2 disk boots directly in QEMU, virt-manager or UTM.
    • 
      
  • Apple Silicon Mac: the arm64 disk runs natively in a VM (UTM, or QEMU with Apple's hypervisor) at full speed, models included.
    • 
    

    
Downloads are split into parts because of GitHub's 2 GB limit. Join them:

    
cat genesis-VERSION.qcow2.zst.*.part | zstd -d -o disk.qcow2
cat genesis-VERSION.iso.*.part > genesis.iso

    
One thing to expect while installing: the step called "Deployment starting" takes 10 to 30 minutes with a progress bar that does not move. It is writing about 13 GB to your disk and it is not stuck. Ctrl+Alt+F3 for a shell where top shows the copy running; Ctrl+Alt+F6 goes back.

    
The joined ISO is about 9 GB (it carries the smallest model pack, so the first boot answers offline), so a USB stick of 16 GB or more is needed. Write it with Fedora Media Writer, or sudo dd if=genesis.iso of=/dev/sdX bs=4M status=progress oflag=sync — the whole stick is overwritten. Nothing is downloaded during the install: the ISO carries the whole system, so the machine can be offline until the first boot.

    
Hardware

    
    
      
  • Any x86_64 PC: the standard image. At first run Genesis measures this machine and keeps whichever device was actually fastest.
    • 
      
  • NVIDIA, Turing or newer (GTX 16xx, RTX 20xx and later): install the standard image, then sudo bootc switch ghcr.io/matijagorsek/genesis:stable-nvidia and restart. Untested on real hardware so far.
    • 
      
  • NVIDIA, Maxwell or Pascal (GTX 9xx, GTX 10xx): do not switch to the NVIDIA flavour. The open kernel modules do not support these cards; the standard image runs them through Mesa.
    • 
      
  • No usable GPU: Genesis still works. The wizard picks a small pack; replies take seconds, app building is slow or limited, and every pack card says what to expect.
    • 
      
  • Apple Silicon Mac: the arm64 flavour in a VM, natively. Models run on the CPU inside the VM.
    • 
      
  • Tested so far: one Intel laptop, virtual machines on x86_64 and Apple Silicon. Real hardware reports are welcome: genesis-report --send, or open a "Hardware report" issue.
    •

Alpha. The prebuilt qcow2 disks are for trying Genesis in a virtual machine: they carry a known account, genesis / genesis, so the boot tests and the weekly evaluation can drive them. The installer ISO has no account at all — it asks you to make one, and Genesis asks again on the console if the installer did not.
